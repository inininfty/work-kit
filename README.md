# work-kit

一个**可升级的工作壳**：把「做完了」变成可执行的判据，把「我记得」变成可回查的账本。
它只装机制，不装经验——经验由你在 `data/` 里慢慢填。

## 它是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 三本账：任务、清单、修改 | 不是笔记软件 |
| 一条闸门：退出码即结论 | 不是 AI 模型 |
| 一套自配置：路径由 `init` 问出来 | 不是任何学科的题库 |
| 一个可升级的壳 + 你的数据 | 不是「装完就聪明」的魔法 |

**壳里没有任何领域内容、没有任何人的路径、没有任何经验条目。**

## 0.4.4：区分普通讨论与资产操作（2026-11-08）

普通答疑、相关只读检索和局部计算不进入工程任务登记/审批/检查；需要检索时先定位再读片段，材料足够时不强制查库。
保存/导出按明确路径做文件操作登记和必要检查，不自动提高领域审核等级；明确保存指令覆盖本次范围，不反复求批。只读、覆盖/删除确认保留。
项目代码、规则、配置、安装和发布沿用工程流程。领域自检、计算工具或独立复核按相应请求和协议；壳不定义学科审核规则，也不声称检查器自动识别请求类别。
步骤强度看不确定性、影响范围、可逆性与依赖；小样解决关键不确定性后恢复直接执行。同一问题的追问不反复建单，检索失败不自动授权修环境，无关工程异常不阻塞普通讨论。
本版本仅改指导与版本声明，不改事务、升级、删除、数据/配置或检查器；通过测试不证明模型必然遵循或实际更快。

## 0.4.3：交给 DSH，一键上手（2026-11-08）

把发布包交给 DSH，说“安装到当前项目，读取 START_HERE.md 并完成检查”。DSH 负责解压、定位、找解释器和启动；用户不填写配置、不敲命令。
`bin/start.py` 统一完成初始化 → 根规则接入 → check all → 状态；只读候选需要一次确认。Windows `install.cmd` 使用同一入口并自动寻找 Python 3.11+，不再跳过候选确认。
缺依赖/权限或 DSH 无法读取附件时，报告具体缺项；本包不安装 Python、不修改 DSH 全局配置或 hook，不保证附件传输/解压工具在所有宿主可用。

## 0.4.2：按需推进（2026-11-08）

默认单 Agent 完成一个已批准的任务；流程强度由不确定性、影响范围、可逆性与依赖决定。

| 步骤 | 触发条件 | 边界 |
|---|---|---|
| 讨论 | 现有材料无法核验的实质歧义 | 已有明确授权不重复确认；范围与权限不能猜 |
| 计划 | 多步有依赖或容易遗漏 | 小任务几句话；不强制另建计划文件 |
| 小样 | 关键假设影响可行性或返工成本 | 先定成功/失败信号，正式结果仍需验收 |
| 分工 | 独立子任务、明确收益和授权 | 不按周期长短自动增开；当前任务指定一个正式状态写入方 |
| 交接 | 跨会话或跨阶段 | 现有账本保留目标、授权、证据、阻塞、下一步；不另建账本 |
| 经验 | 发现值得跨任务复用的内容 | 先记候选与边界，后续验证；不按条数自动晋升 |

先索引、标题或 ID 定位，再读命中片段。同输入、同版本、同范围有效证据可以复用；变更、失败或未解疑点才扩查。
上述工程/保存任务仍按各自范围登记、批准和检查，工程必需 `check all` 与破坏性确认不减免；普通讨论不进入这些手续，复用不代替适用的必跑检查。
验收选择与产物相符的测试、diff、回读或真实运行；交付时直接展示关键 diff，并说明未验证项。
这是执行指导更新，版本、状态、锁、事务、边界的原校验逻辑不变；不声称检查器能强制模型选择单 Agent 或证明耗时下降。
升级仍不覆盖用户数据与配置，本次不提供自动升级其他已装实例的承诺。

## 0.4.1 候选：可靠性修复

- 锁内分配编号；三账统一事务；中断用 `kit recover`，活锁不因年龄被抢。
- 完成必须有真实文件证据，新增/修改产物绑定哈希；不存在或已变更的产出不能报全过。
- 文件名可含空格，重复传 `--files "My Notes.md" --files other.md`；逗号仍可分隔。
- 删除拒绝工作区根、只读根、壳祖先、VCS、链接和重叠目标；先完整备份验证，恢复不覆盖冲突。
- 升级预检完整发布，冲突只生成候选，返回 3；活动版不混装。失败回滚且保留 `.runtime/upgrades` 证据。
- `data/` 与本机 `config/` 升级时逐字节保留；运行安装状态移到 `.runtime/`，旧 `config/kit.state.json` 只读兼容。
- `kit recall 关键词` 返回带 ID 的经验来源；不自动写回或晋升。
- **兼容变化**：旧的叙述性 evidence 不再足够；必须给真实文件或 `file:相对路径`。旧版本删除批次保留但不自动恢复，须人工核对其不完整目录哈希。
- 新版 `log --complete` 的文件可自动作为 evidence；需要工程登记的只读调研请显式给报告文件；普通答疑/相关检索按0.4.4边界不建单。批准字段只记录事件，不认证用户身份。

## 删除：安全那一种

```bash
python bin/kit.py remove a.txt b/          # 只打印计划
python bin/kit.py remove a.txt b/ --yes    # 移进回收站
python bin/kit.py trash                    # 看回收站
python bin/kit.py restore <stamp>          # 放回并校验哈希
```

工作区外、壳目录、`.git` 里的路径整单拒收，磁盘零变化。

不带 `--yes` 时打印的是**删除计划**：每一项的绝对路径、类型、大小/文件数、合计，以及影响与恢复方式。
把计划给用户看，等他回「删除」或「确认」再加 `--yes`（R14；这也是本壳自己守的四条硬规矩之一）。

## 升级：一条命令

```bash
python bin/kit.py update --source <新版本目录>   # 第一次
python bin/kit.py update                          # 以后
```

升级 → 重写规则指针 → 跑闸门，一条命令做完。

## 日常怎么用（不用手写 JSON）

```bash
python bin/kit.py task new "把要做的事写清楚" --next "第一步"
python bin/kit.py change new T-001 --files a.py --budget 100
python bin/kit.py change approve C-001
python bin/kit.py log C-001 --created a.py --complete
python bin/kit.py status
```

- `change new` 建出来是 **proposed**，要 `approve` 才变 `doing`、才算数；`log` 会拒绝未批准的清单。
- `log` 写修改记录，并把清单标 done；加 `--complete` 连任务一起标 done。
- `task done` 必须带 `--evidence`。

安装时会在**工作区根**的 `AGENTS.md` 里自动写一段标记块，指向 `work-kit/AGENTS.md`。
这样整个工作区都守这套规矩，而规则本体仍然只有一份。

## 双击安装（Windows 备选）

把 work-kit 放入目标项目，双击 `install.cmd`；自动寻找 Python 3.11+ 并运行同一启动入口。
没有只读候选则直接完成；有候选则展示并等确认，拒绝或取消不写配置。

命令行等价（由 DSH 运行，不要求用户输入）：

```bash
python bin/start.py
```

确认全部只读候选后才添加 `--confirm-readonly`。已有实例再次启动不重置配置或数据；已有工作壳升级按原 update 流程。

## 10 分钟装好（手动）

```
1. 把整个 work-kit/ 复制到目标工作区（放在目标工作区的直属 work-kit 子目录）
2. python bin/init.py        # 问三个问题，写 config，建空账本
3. python bin/check.py all   # 全 pass 即装好
```

`init` 问的三个问题：

1. 这个工作区在哪（默认：壳的上一级目录）
2. 一句话：它要做什么
3. 哪些子目录是只读的（对方的资产）——**只列工作区下一层，不外扫**

全部可以直接回车跳过。

## 三个命令

```bash
python bin/init.py       # 初始化 / 重来（--force）
python bin/check.py all  # 闸门：0 全过 / 1 有失败 / 2 未初始化
python bin/upgrade.py    # 看壳有没有被改过；--source <新版> --apply 升级
```

辅助：

```bash
python bin/check.py status    # 状态摘要（按需生成，不常驻上下文）
python bin/check.py privacy   # 只扫绝对路径与敏感词
python bin/check.py package   # 打包前检查 + 打印发布白名单
```

## 闸门查什么

| 检查 | 防的是 |
|---|---|
| 任务 `done`/`verified` 必须有 `evidence` | 「我说做完了」 |
| 清单 `done` 必须有修改记录 | 「承诺了但没做」 |
| 修改记录必须指向真实任务 | 孤儿记录 |
| 账本之间引用必须可解析 | 断链 |
| 状态只用六个词（清单四档：proposed/doing/done/abandoned） | 自创状态 |
| 目录里不能有未申报文件 | 偷偷多出来的东西 |
| 壳文件里不能有绝对路径 | 把本机路径带出去 |
| 申报路径必须是纯相对路径（无盘符、无控制字符、无 `..`；合法空格保留） | 一个元素塞两个路径 |
| 修改记录不得越界（工作区外 / 只读根 / `.git` / 壳目录） | 写了别人的目录还不报 |
| 清单与修改账本双向对账（承诺的要真做，做了的要真承诺） | 承诺与落地两张皮 |
| `evidence` 里像路径的必须真存在 | 拿不存在的文件当证据 |
| 清单 `done` 必须有 `approved_at` | 没批准就完成 |

## 壳与数据的分界

| 路径 | 谁的 | 升级时 |
|---|---|---|
| `bin/ core/ schemas/ AGENTS.md README.md kit.json` | 壳 | 覆盖 |
| `data/` | 你 | **永不触碰** |
| `config/` | 本机 | **永不触碰、不进发布包** |

升级时如果某个壳文件**你改过**，它不会被覆盖，而是生成 `同名.new`，让你自己合。

## 隐私：三道闸

1. `config/` 从不进发布白名单；
2. `check.py package` 跑绝对路径与敏感词扫描，扫到就非零退出；
3. 目录里出现白名单外的文件，`check.py all` 直接报红。

**发布方式**：从全新目录、全新 git 仓库导出，不要从带历史的仓库里 split。

想让扫描拦下特定词（用户名、公司名），写进 `config/kit.config.json` 的
`privacy_tokens` 数组。它只存在本机。

## 升级

```bash
python bin/upgrade.py --source ../work-kit-0.2.0 --apply
```

规则：

- 你没改过 + 上游改了 → 覆盖
- 你改过 + 上游也改了 → 只生成 `.new`，不覆盖
- `data/`、`config/` → 一个字节都不动
- 上游删掉的文件 → 报告，不替你删

## 0.4.0 变了什么（2026-10-28）

- **R14 进壳**：`remove` 的计划给出绝对路径 / 类型 / 大小或文件数 / 合计，并写清影响与恢复；
  不带 `--yes` 时磁盘零变化。AGENTS.md 的「三条硬规矩」变四条，删除节写了两步确认与覆盖前备份。
- **清单语义定死**：`change new` 建的是 `proposed`（未批准），`approve` 才变 `doing`；`log` 拒绝未批准的清单。
  这样做的好处是「提案」与「在飞」不再共用一个 `doing`。
- **修 `--files` 分项 bug**：原来只按逗号切，`--files a b` 会把两个路径并成一个数组元素（companion-bot 的 C-053 实测）。
  这是 0.4.0 的历史行为；0.4.1 改为重复参数或逗号分隔，空格属于文件名。
- **新增四项闸门**：申报路径纯度、修改记录越界（工作区外 / 只读根 / `.git` / 壳目录）、清单↔修改双向对账、
  `evidence` 里像路径的必须真存在；另加「清单 done 必须有 approved_at」。
- **0.4.0 当时的欠账**：工作区未申报产出的全量扫描、状态机与角色、真值源占位。0.4.1 只补最小状态约束，其余仍不宣称实现；当前边界见 `CONTRACT.md`。

## 常见问题

**Q：为什么没配置就拒绝写入？**
A：有配置才谈得上「哪些目录只读」。缺配置时放行，等于到了别人机器上守卫不存在。

**Q：账本能不能用数据库？**
A：可以，但先别。纯文本的好处是能 diff、能 grep、能进 git，坏了能手修。

**Q：经验要写多少才有用？**
A：不设条数门槛。有来源、适用边界和后续验证的记录才有用；用 `kit recall 关键词` 按需检索。

**Q：能不能只用闸门、不用账本？**
A：可以。`core/ledger.py` 是独立模块，闸门只依赖它的读取函数。
